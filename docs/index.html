Code review when agents write the code

      
Ask what could go wrong, and which check catches it

      
At Anthropic, Claude writes most of the Claude Code codebase, and people can't read every line. So review becomes layers, and people put their attention where the risk is. From Solving code review at Anthropic.

    

    

      
Before the PR
The agent proves its work: runs the tests and shows the output, rather than saying it's done.

      
On every PR
AI review against REVIEW.md, which says what failure looks like in this repo, caps nits and demands file:line evidence.

      
In the PR body
How it was tested, how risky it is, and how to revert it.

      
The human call
Approval scales with the risk of the change, not who wrote it.

    

    

      

        
RiskExamplesPeople who approve

        
          
LowDocs, copy, additive changes behind a flagNone once checks are green

          
MediumOrdinary product changesOne

          
HighAuth, baskets and checkout, CI, releasesTwo
